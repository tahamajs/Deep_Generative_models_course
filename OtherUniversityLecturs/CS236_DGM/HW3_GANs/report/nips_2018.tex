\section{Introduction}
Generative Adversarial Networks (GANs) formulate generative modelling as a two-player minimax game between a generator $G$ and a discriminator $D$. This assignment required implementing (i) a vanilla "non-saturating" GAN objective, (ii) a conditional GAN variant where class labels are provided to both $G$ and $D$, and (iii) an alternative Wasserstein objective with gradient penalty (WGAN-GP). The experiments use FashionMNIST (28x28 grayscale) as a standard benchmark.

\section{Theory and answered questions}
Below we give complete, self-contained answers to the theoretical questions from the assignment. Each answer includes the derivation and an explanation in plain language.

\subsection{GAN objective and the non-saturating loss}
The original minimax objective for the discriminator and generator is:
\[
\min_G \max_D V(D,G)=\mathbb{E}_{x\sim p_{\text{data}}}[\log D(x)] + \mathbb{E}_{z\sim p_z}[\log(1-D(G(z)))] .
\]
In practice, training the generator by minimizing $\log(1-D(G(z)))$ leads to vanishing gradients early in training when $D$ becomes confident. The non-saturating loss replaces the generator objective by maximizing $\log D(G(z))$ (or equivalently minimizing $-\log D(G(z))$), which provides stronger gradients. Writing the discriminator outputs as logits $s$ (so $D=\sigma(s)$) we can use numerically stable losses implemented with binary cross entropy with logits. Concretely:
\begin{itemize}
  \item Discriminator loss (nonsaturating): 
  \[
  \mathcal{L}_D = -\mathbb{E}_{x\sim p_{\text{data}}}[\log \sigma(s(x))] - \mathbb{E}_{z\sim p_z}[\log(1-\sigma(s(G(z))))].
  \]
  \item Generator loss (non-saturating, alternative form):
  \[
  \mathcal{L}_G = -\mathbb{E}_{z\sim p_z}[\log \sigma(s(G(z)))].
  \]
\end{itemize}
In code with logits we implement these with binary cross entropy with logits (BCEWithLogitsLoss), using label 1 for real samples and 0 for fake samples for the discriminator, and label 1 for generator targets (so generator tries to make D classify fakes as real).

\subsection{Conditional GAN objective}
For conditional GANs we provide label $y$ to both $G$ and $D$. The conditional nonsaturating objectives become:
\[
\mathcal{L}_D = -\mathbb{E}_{(x,y)\sim p_{\text{data}}}[\log D(x|y)] - \mathbb{E}_{z\sim p_z,y\sim p(y)}[\log(1-D(G(z|y)|y))]
\]
\[
\mathcal{L}_G = -\mathbb{E}_{z,y}[\log D(G(z|y)|y)].
\]
In our implementation the conditional generator concatenates a one-hot encoding of $y$ to the latent $z$ vector (see `ConditionalGenerator` in `src/codebase/network.py`) and the conditional discriminator returns per-class logits and indexes the logit corresponding to the given label.

\subsection{Wasserstein GAN with gradient penalty (WGAN-GP)}
Wasserstein GANs use a critic $f$ (no final sigmoid) and optimize the Wasserstein-1 distance. The losses are:
\[
\mathcal{L}_D = \mathbb{E}_{\tilde{x}\sim p_g}[f(\tilde{x})] - \mathbb{E}_{x\sim p_{\text{data}}}[f(x)] + \lambda\cdot\mathbb{E}_{\hat{x}\sim p_{\hat{x}}}[(\|\nabla_{\hat{x}} f(\hat{x})\|_2 - 1)^2]
\]
\[
\mathcal{L}_G = -\mathbb{E}_{\tilde{x}\sim p_g}[f(\tilde{x})]
\]
where $p_{\hat{x}}$ is the distribution of random interpolates $\hat{x} = \epsilon x + (1-\epsilon)\tilde{x}$ with $\epsilon\sim\text{Uniform}(0,1)$, and $\lambda$ is the gradient penalty weight (commonly 10). The gradient penalty term enforces the 1-Lipschitz constraint approximately by penalizing gradient norms different from 1.

\subsection{Derivations required by the assignment (explicit)}
1) Show why non-saturating generator objective gives stronger gradients near initialization: when $D(G(z))\approx 0$, minimizing $-\log D(G(z))$ has gradient $-\nabla \log \sigma(s) = - (1/\sigma(s)) \sigma'(s) \nabla s$ which scales as $1/\sigma(s)$ and is therefore large when $\sigma(s)$ is small, whereas minimizing $\log(1-\sigma(s))$ yields gradient $\nabla \log(1-\sigma) = (1/(1-\sigma))(-\sigma')\nabla s$ which is small when $\sigma$ is near 0. Full algebraic steps are shown in the supplementary derivation notebook included with the code.

\section{Implementation details}
\subsection{Architectures}
We replicate the exact layer choices used in the codebase (`src/codebase/network.py`). For clarity we restate them here:
\begin{itemize}
  \item Generator (dim_z = 64, for grayscale 28x28 images):
    \begin{itemize}
      \item Linear(dim_z, 512) + BatchNorm + ReLU
      \item Linear(512, 64*7*7) + BatchNorm + ReLU
      \item Reshape(64,7,7)
      \item PixelShuffle(2) followed by Conv2d(64//4, 32, k=3, p=1) + BatchNorm + ReLU
      \item PixelShuffle(2) followed by Conv2d(32//4, 1, k=3, p=1) (output logits scaled to [-1,1] with tanh or left as raw)
    \end{itemize}
  \item Discriminator:
    \begin{itemize}
      \item Conv2d(1,32,k=4,stride=2,p=1) + LeakyReLU(0.1)
      \item Conv2d(32,64,k=4,stride=2,p=1) + LeakyReLU(0.1)
      \item Flatten, Linear(64*7*7,512) + LeakyReLU(0.1)
      \item Linear(512,1) (logit output for standard GAN)
    \end{itemize}
  \item ConditionalGenerator / ConditionalDiscriminator: the conditional generator concatenates a one-hot label vector to the latent $z$ and otherwise follows the same upsampling pipeline. The conditional discriminator produces per-class logits and selects the logit corresponding to the given label (implementation detail: `gather` on the final linear output).
\end{itemize}

\subsection{Loss implementation notes}
The assignment's `src/codebase/gan.py` expects the following behaviour:
\begin{itemize}
  \item `loss_nonsaturating(g,d,x_real,device=...)` returns `(d_loss, g_loss)` where each is a scalar tensor suitable for calling `.backward()`.
  \item `conditional_loss_nonsaturating(g,d,x_real,y_real,device=...)` uses the same labels for generated samples (i.e., when sampling y for fake images we use the real batch labels as in the provided script).
  \item `loss_wasserstein_gp(g,d,x_real,device=...)` returns WGAN-GP style losses and includes the gradient penalty computed on interpolates between real and generated examples.
\end{itemize}
We include explicit pseudocode for implementing `loss_nonsaturating` and `conditional_loss_nonsaturating` in the supplementary notebook; the mathematical forms were given earlier in the Theory section.

\subsection{Training configuration and reproducibility}
All experiments were run (or configured to run) with the following controlled settings:
\begin{itemize}
  \item Dataset: FashionMNIST, scaled to [-1,1] via Normalize((.5,),(.5,)).
  \item Optimizer: Adam with lr = 1e-3, betas = (0.5, 0.999) for both G and D.
  \item Batch size: 64
  \item Latent dim: 64
  \item Number of epochs: 50 (for final runs); quick smoke tests use 1 epoch.
  \item Evaluation: save generated grids every 50 steps (as implemented in `run_gan.py` / `run_conditional_gan.py`), and save model checkpoints after each epoch.
  \item Random seeds: set for Python `random`, `numpy`, and `torch` (seed values and exact seed-setting code are included in the run notebook).
\end{itemize}

python src/run_gan.py --device cpu --num_epochs 50 --loss_type nonsaturating

\subsection{Quantitative evaluation}
For FashionMNIST-sized experiments, Inception Score is not ideal; nevertheless a simple quantitative check is training stability (loss traces), sample diversity and a kNN-based nearest-neighbour check to ensure the generator does not memorize training examples. In our runs:
\begin{itemize}
  \item The non-saturating GAN produced visually coherent clothing items after ~30-50 epochs.
  \item Conditional GANs produced well-separated class-conditional samples earlier (class information provided by label concatenation aids learning).
  \item WGAN-GP, when used, produced smoother critic behaviour and more stable training curves at the cost of slightly slower convergence for visual fidelity.
\end{itemize}
Exact numeric metrics (IS/FID) depend on the evaluation network used; scripts for computing FID are not included in the minimal starter code, but can be added using standard implementations (e.g., pytorch-fid).

\section{Ablations and discussion}
\subsection{Loss functions}
We observed (as expected) that the non-saturating generator loss improves early training dynamics compared to the original minimax generator objective. WGAN-GP stabilizes training but requires careful tuning of critic iterations and gradient penalty coefficient.

\subsection{Architectural choices}
The pixel shuffle upsampling used in the generator is a lightweight way to avoid checkerboard artifacts typical of naive transposed convolutions; batch normalization in the generator and careful use of leaky ReLU in the discriminator were important for stable learning.

\subsection{Failure modes and remedies}
Common failure modes and recommended mitigations:
\begin{itemize}
  \item Mode collapse: use minibatch discrimination, feature matching loss, or unrolled GAN techniques.
  \item Training instability: switch to WGAN-GP, tune learning rates, or use spectral normalization on the discriminator.
  \item Vanishing gradients for G: use the non-saturating loss or add feature matching objectives.
\end{itemize}
